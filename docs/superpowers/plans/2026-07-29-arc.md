# Automatic Reference Counting (ARC) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every heap value (text/list/map) reclaimed when its last reference dies — all `.leaks` goldens to zero — via compiler-emitted retain/release, replacing 4e's escape-analysis machinery entirely.

**Architecture:** Each value's non-relocatable box gains an `int32_t rc` (born 1). clarusc's lowering emits `IRetain`/`IRelease` IR intrinsics for named slots (assignment retain-new-then-release-old, +1-transfer returns, counted container elements, record retain/release walks); the printer's Task-6 statement-temp tracker upgrades from free to release and finally covers call results. Migration is staged by slot class — temps/call-results → locals → container elements → globals/window-vars → records — with `*_free` aliased to `*_release` from the first task so every intermediate state preserves the no-UAF invariant. The 4e escape apparatus is deleted at the end.

**Tech Stack:** C89 (rt_core.inc, both runtimes via the rt_mem seam), Clarus (clarusc/{ir,lower,cprint}.cla), Go test harness (strict+paranoid leak gate).

**Spec:** `docs/superpowers/specs/2026-07-29-arc-design.md` (approved 2026-07-29).

## Global Constraints

- Branch: `arc`. Commit after every task; `main` stays green; merge only on request.
- Go compiler (`internal/`) FROZEN — test files are harness and may change; `internal/cprint/cprint.go` etc. may not.
- rt.h ABI: additions only; `rt_text*`/`rt_list*`/`rt_map*` stay stable plain pointers.
- Bootstrap one-liner unchanged: `cc -I internal/build/rt -o clarusc clarusc/clarusc.c internal/build/rt/rt.c`.
- Every clarusc-touching task regenerates the snapshot (`go run ./cmd/clarus build -o /tmp/clarusc clarusc/main.cla && /tmp/clarusc emit -o clarusc/clarusc.c clarusc/main.cla`) and, when emitted C changes, all `testdata/emitui/*.c.golden` (emit each fixture with /tmp/clarusc built from CURRENT source) — then `go test ./internal/selfhost ./internal/emitui -count=1`.
- `clarusc/{ir,lower,cprint,main,check}.cla` are pure ASCII (Edit-tool safe); never Edit `lex.cla`/`lib.cla`/`tok.cla` (MacRoman bytes).
- clarusc's own source uses no new language features (conservative subset rule for the bootstrap).
- **Migration invariant, every task:** leaks may exist mid-branch (tracked by exact-match `.leaks` goldens, updated per task, falling monotonically); UAF/double-free never. A slot class not yet migrated keeps its 4e qualification; a migrated class retains everything it stores.
- The strict corpus gate (`TestEmitDifferential`, CLARUS_MEM_STRICT+PARANOID) is the per-task canary: run `go test ./internal/selfhost -run TestEmitDifferential -count=1` after every lowering change; any crash = your bug.

- Mac gates (`CLARUS_MAC_TESTS=1 go test ./internal/mactest`) run in Tasks 1 (smoke) and 9 (full): FOREGROUND Bash, timeout 600000 per call, chunked (`-run TestSuiteOnMac`, then runerr/abort, then UI scenarios in groups of 4-5). Never run_in_background; never end a turn mid-gate.

### Task 7: Record retain/release walks at every copy site

**Files:**
- Modify: `clarusc/lower.cla` (record assignment/param/return/element sites mark + emit walk intrinsics)
- Modify: `clarusc/cprint.cla` (param entry/exit walks in `cpEmitFunc` if lowered params can't carry them — prefer lowering)
- Modify: `testdata/run/*.leaks` (+ new fixtures), snapshot, emitui goldens

**Interfaces:**
- Consumes: Task 2's `clar_retain_<Rec>`/`clar_release_<Rec>` emitters + IRetain/IRelease KRec dispatch.
- Produces: every record copy retain-walks, every record death release-walks. Site checklist (THE review checklist — each gets an emitted-C probe in the report):
  1. record assignment (`r1 = r2`): release-walk old dst, byte-copy, retain-walk dst (walking dst AFTER the copy retains exactly the handles now held; release-old-FIRST here is safe because the byte copy hasn't happened yet — note the order differs from scalar-handle stores and document why: self-assign `r = r` release-then-retain on the same handles would drop to 0 mid-sequence → GUARD: skip both walks when src and dst are the same lvalue, or retain-walk src first via a temp copy; pick the temp-copy order: byte-copy src to a temp, retain-walk temp, release-walk dst, byte-copy temp to dst — always safe, costs one struct copy)
  2. record param: retain-walk at function entry, release-walk on every exit (lowFuncBody knows param types)
  3. record return: retain-walk the materialized return value (+1 transfer); caller's receipt is a tracked record temp — release-walk at end of statement unless handed off (extends the Task 3 tracker to record temps; fpUiEditStmt's record temps — the 4e deferred minor — get covered here)
  4. record container elements: store = temp-copy + retain-walk (mirror site 1); removal = release-walk the removed copy... CAREFUL: `pop(out)` byte-copies into `out` which already held a record — release-walk `out`'s old value first, then transfer (no retain — pop transfers)
  5. record locals: release-walk at scope exit + quit
  6. record globals / window state fields: release-walks in cl_free_globals / clar_ui_release (Task 2's cpEmitRelease KRec recursion already does this — verify)
  7. fixed arrays of records: element loops at each of the above (mirror cpDefaultInit's KArr recursion)
  - Form buffers: NO-OP by construction — `form for T` requires every field by-value (reference Ch10); assert that assumption with a grep for the check in check.cla and cite it in a comment.
