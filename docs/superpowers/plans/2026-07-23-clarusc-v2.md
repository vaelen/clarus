# clarusc v2 Implementation Plan — C Emission + Self-Hosting Bootstrap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn clarusc from a checker into a full compiler that emits C for the host-supported language, self-compiles, and reaches a byte-identical three-stage bootstrap fixed point with a committed `clarusc.c` snapshot.

**Architecture:** Port the Go backend (`internal/ir`, `internal/lower`, `internal/cprint`, ~2,900 LOC) into three new clarusc modules (`ir.cla`, `lower.cla`, `cprint.cla`) in v1's arena idiom, reusing the existing C runtime (`internal/build/rt/rt.{c,h}`) unchanged. clarusc emits the identical `rt_*` ABI, so compiled programs behave identically by construction. Verified by a behavior-parity differential (clarusc-emit → `cc` + `rt.c` → run, compared to the existing `testdata/run` `.out` oracle) plus the bootstrap fixed point.

**Tech Stack:** Clarus (the `clarusc/*.cla` modules), the Go compiler (reference + bootstrap builder), C runtime (`internal/build/rt`), Go test harness (`internal/selfhost`), `cc`.

## Global Constraints

- **The Go backend is the byte-exact porting spec.** Each task names the exact `internal/{ir,lower,cprint}` file and function to port. Where a Go function's behavior and this plan's prose ever disagree, the Go source wins — read it. (Same porting-contract discipline v1 used for the front end.)
- **Arena idiom** (mandatory, follow `clarusc/ast.cla` and `clarusc/check.cla`): every IR node lives in a `list of Node` arena, referenced by `int` index, `-1` is nil, all field access goes through thin accessor functions, one global string-intern pool (the existing `strPool`/`intern` in `lib.cla`) is reused for all names and string literals. No recursive types.
- **Runtime reused unchanged.** clarusc emits calls against the exact ABI in `internal/build/rt/rt.h` (43 `rt_*` functions). Do NOT modify `rt.c`/`rt.h`. C compilation reuses the same step `internal/build/build.go` uses: `cc -std=c99 -O1 main.c rt.c -o out` via `build.CCPath()`, with `rt.h`/`rt.c` written into the same workdir.
- **Verification contract:** behavior parity (not C-text identity vs Go). A clarusc-emitted program's stdout/stderr/exit must match the `testdata/run` `.out`/`.log`/`.exit` oracle (which the Go build already matches). PLUS the bootstrap fixed point: `stage2.c == stage3.c` byte-identical.
- **Deterministic emission** (the fixed point requires it): mirror Go's determinism exactly — per-function temp counter `tN` (monotonic, never reset within a function, never reused), one program-wide switch-temp counter `__switchN`, fixed buffer assembly order, map iteration only in the language's sorted-by-key order. No address-dependent or nondeterministic output.
- **Conservative-subset rule:** clarusc's own source stays on the current language feature set (do not adopt newer features inside `clarusc/*.cla`).
